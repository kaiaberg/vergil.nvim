1. INTRODUCTION                                                 *vergil-intro*

vergil helps you write prompts for Claude Code in the Neovim instance that
Claude Code's `Ctrl+G` opens. It completes file references and skills,
selects exact lines with real Vim motions, inserts verbatim snippets,
previews and opens references, and flags references that are likely
mistakes.

vergil only helps write the prompt. It never sends anything, never runs
skills, and never changes text you didn't ask it to change. It runs as an
LSP server inside Neovim, so hover, go-to-definition, diagnostics and code
actions use Neovim's usual LSP mappings.

==============================================================================
2. SETUP                                                        *vergil-setup*

Requirements: Neovim 0.11 or newer. Optional: Claude Code, to hand prompts
over with `Ctrl+G`; a completion engine (blink.cmp, nvim-cmp, or built-in
completion); ripgrep, fd or git for file discovery; and a Nerd Font for
completion icons.

Claude Code opens `$VISUAL` before `$EDITOR`, so set: >sh
  export VISUAL=nvim
<
vergil works without |vergil.setup()|. It turns itself on in buffers whose
file name matches `claude-prompt-*.md` (only the name is checked, not the
directory) and nowhere else. Use |:Vergil-enable| for other buffers.

The project root is the directory Neovim started in, which is where Claude
Code runs. It is captured once and survives |:cd|. Set `root` to override it.

                                                       *vergil-ahead-of-time*
vergil doesn't need a running agent. To draft prompts or a plan in advance,
run |:Vergil-enable| in any Markdown buffer, or add file names to
`activation.filename_patterns`, e.g. `{ "claude-prompt-*.md", "*.prompt.md" }`.
Start Neovim in the project the prompt is for, since paths are relative to
the root.

Run |:checkhealth| `vergil` to check the setup.

3. REFERENCES: ATTACH AND MENTION                          *vergil-references*

                                                           *vergil-attachment*
`@path` attaches a file: the agent loads the whole file into the
conversation. Paths with spaces are quoted: `@"docs/my notes.md"`. A range
written on an attachment (`@file#L3`) usually doesn't limit it, and large
files may be skipped or cut (|vergil-observed|).

                                                              *vergil-mention*
`` `path` `` mentions a file: the agent knows where to look and reads it
only if needed. Mentions can point at lines: `` `path#L12` ``, `` `path#L12-L35` ``
(the "github" format) or `` `path:12-35` `` (the "colon" format).

Attach the files the agent must read in full, once; mention everything
else.
Mentions of an attached file are never flagged.

                                                             *vergil-observed*
Observed behaviour, last checked with Claude Code 2.1.319. None of it is
documented and any release may change it; |:checkhealth| `vergil` shows
whether your version differs. vergil inserts plain `@path` references and
Markdown mentions either way, and diagnostics only hint at what the agent
might do.
- `@` starts a reference only at line start or after whitespace, so `(@a)`,
  `"@a"`, `` `@a` `` and `me@example.com` are not references.
- Trailing punctuation after an unquoted path is not part of it:
  `@a.ts),` attaches `a.ts`.
- `@file#L5` attaches the whole file; the range is ignored.
- Markdown is ignored: `@Override` inside fenced code is attached when a file
  of that name exists.
- Attachments above about 25k tokens are dropped without notice; from 256 KB
  the agent is told the file was too large.
- Exiting the editor with an error discards the edit.
- Unchanged pasted text collapses again after `Ctrl+G`, except a paste at the
  very end of the prompt.
- If the editor fails to start, the prompt stays as it was, with no error.

                                                         *vergil-:Vergil-toggle*
|:Vergil-toggle| and the "Convert" code action switch between the two:
`@file` <-> `` `file` ``, and `` `file#L12-L35` `` becomes
`@file` `` `file#L12-L35` ``, so the range isn't lost.

4. COMPLETION                                              *vergil-completion*

- `@` at line start or after whitespace completes files to attach.
- `@@` completes files to mention.
- `/` at line start or after whitespace completes skills and commands.

Matching is fuzzy and ranked by vergil, so every engine shows the same order.
Each file shows its size; files already attached are marked "attached".

Outside the project, a query starting with `~` or `/` completes one
directory at a time, like a shell: `@~` lists your home directory, `@~/co`
its entries matching "co", `@/etc/` the files in /etc. Directories end in
`/`; dotfiles show once the name starts with `.`.
Nothing is offered inside fenced code.

Manual completion (`<C-Space>` in most setups) on an existing reference
re-searches it in place: the query is the path up to the cursor, and
accepting replaces the whole reference. Backspace inside a reference reopens
a menu the engine closed (`completion.reopen_on_backspace`).

Engine notes:
- blink.cmp: return only `{ "lsp" }` from `sources.default` when
  `vim.b.vergil_enabled` is set, so snippets don't pop up in prose.
- nvim-cmp: on the |VergilEnable| event, set buffer-local sources with
  `cmp.setup.buffer`.
- Built-in completion: set `completion.native = true` and add `popup` to
  'completeopt' to see skill descriptions. Leave it off with a completion
  plugin, or two menus open.

                                                              *vergil-picker*
The picker has tabs for everything that can go into a prompt: All, Files,
Changed, Branches and Commits (in a git repository), and Skills;
`picker.tabs` sets which and in what order (a tab left out is gone from All
too). Branches insert `` `name` (branch) ``. |:Vergil-pick| opens
it on a tab; <C-g> (preset) in Insert mode opens it on what you're typing
(`@sess`, `@@sess`, `/rev` on their tab, any other word on All) and
replaces that with your choice; inside a word it searches for what's
before the cursor and replaces the whole word. In Normal mode, <C-g> turns
what's under the cursor into a reference: a reference, `/skill` or word
(without surrounding punctuation) is the search and is replaced; on
whitespace the search is empty and the choice goes there. From Normal mode,
|:Vergil-pick| inserts after the word under the cursor, not inside it. Choosing or closing returns to the mode it was opened
from. Type to filter; the query stays when switching tabs, and tabs cycle.

For a file outside the project, start the search with `~` or `/` in Files
(`~` in All, where `/` searches skills): it lists that directory, like
completion (|vergil-completion|). <CR> on a directory opens it; mark it with
<Tab> to insert the directory itself.

  <CR>                      Insert the item, or every marked one; open a
                            directory
  <Tab> <S-Tab>             Mark, unmark; a mark shows in every tab
  <C-n> <C-p> <Down> <Up>   Move
  <C-Right> <C-l> <M-l>     Next tab
  <C-Left> <C-h> <M-h>      Previous tab
  <M-1> .. <M-9>            Go to a tab (<C-1>.. where the terminal sends it)
  <C-t>                     Switch between attaching and mentioning files,
                            for the next marks
  <C-o>                     Join several items with spaces, commas, or one
                            per line
  <C-r>                     Select lines of the file
  <C-d>                     Insert a commit's diff
  <C-f> <C-b>               Scroll the preview
  <Esc> <C-c>               Close

Marked items show a sign: `@` attach, `` ` `` mention, `/` skill, `◆` commit,
`⎇` branch.
A mark keeps the attach/mention mode it was marked with. The Marked panel
under the preview lists the marks in order, with the text each inserts.

`picker.keys` overrides keys: `{ next_tab = { "<C-l>" } }` (names: confirm,
close, down, up, mark, unmark, next_tab, prev_tab, scroll_down, scroll_up,
toggle_mode, separator, select_lines, diff).
`picker.on_trigger = true` opens the picker on `@` and `/` instead of the
inline menu.

5. LINE SELECTION AND SNIPPETS                       *vergil-lines* *vergil-#*

Type `#` directly after a reference that names a text file, or use
|:Vergil-range|. A float opens with a read-only copy of the file, highlighted
and numbered. The real file is never loaded, so no swapfile and no LSP client
are involved. Use any motion, search, count or |V|, then:

  <CR>     Insert a mention with the selected lines (or the current line;
           a count selects that many lines). It replaces the reference and
           the `#`.
  gs       Insert a verbatim snippet. The reference becomes the snippet's
           header; if it stood alone on its line, the snippet replaces the
           line.
  gb       Insert the mention, and the snippet below the line.
  gO       List the file's functions, classes and methods; choosing one
           selects its lines (see |vergil-symbols|).
  q <Esc>  Cancel: removes the `#`, nothing else. <Esc> in Visual mode only
           leaves Visual mode.

A selected range always produces a mention: selecting lines from an `@`
attachment removes the `@`.

                                                             *vergil-snippet*
Snippets have a mention header (never `@`, which would load the code again),
keep whitespace exactly, use a fence longer than any backtick run in the
code, and take the language from the file name:
>markdown
  From `src/auth/session.ts#L12-L15`:

  ```typescript
  if (!token) {
    throw new AuthError();
  }
  ```
<
|:Vergil-snippet| does the same for a ranged reference already in the prompt.

                                                             *vergil-symbols*
When the selected lines are exactly one function, class or method, its name
follows the range: `` `src/range.lua#L96-L135` (`M.apply`) ``, also in a
snippet's header and with |:Vergil-send|. Whether the lines were picked with
`gO` or by hand doesn't matter. The agent gets exact lines and a name to fall
back on, and vergil warns when the range no longer matches the name, with a
code action to update it. `mention.symbols = false` leaves names out.

Symbols come from Neovim's treesitter parser for the file's language; no
LSP is involved. Neovim ships parsers for Lua, C, Vimscript and a few more;
install others (e.g. with nvim-treesitter) for more languages. Without a
parser, `gO` says so and nothing else changes. Callbacks passed as arguments
aren't listed; nested symbols are qualified, e.g. `Session.enable`.

6. SKILLS AND COMMANDS                                         *vergil-skills*

`/` lists skills and commands from:
- the project: `.claude/skills/<name>/SKILL.md` and `.claude/commands/**.md`
  in the root and every parent up to the repository root,
- your personal `~/.claude`, and the managed settings directory,
- synced claude.ai skills, and enabled plugins (best effort, as
  `/<plugin>:<name>`),
- `skills.extra_items` from your configuration, e.g. built-ins like /compact.

A skill's command is its frontmatter `name`, else its directory name;
`commands/sub/deep.md` is `/sub:deep`. On a name clash a skill beats a
command, and personal beats project; hover lists what an item overrides.
Without a description, the first line of the body is shown. Accepting
inserts the command only. Hover (`K`) and go-to-definition (`gd`) work on
`/skill` in the prompt.

==============================================================================
7. PREVIEW AND OPEN                                           *vergil-preview*

`K` (hover) previews a reference: size, line count, and the referenced lines
or the start of the file. Directories list their entries. On a `/skill` it
shows the description and where it's defined.

`gd` or `<C-]>` opens the target at its line in the current window.
|:Vergil-open| `split`, `vsplit` or `tab` opens it elsewhere. With
`return_to_prompt` (default), `:q` in a file opened this way returns to the
prompt instead of exiting Neovim and handing back to Claude Code.

                                                                *vergil-send*
The way back: select lines in the opened file itself, with any motion, text
object or search, and send them to the prompt with |:Vergil-send| (or <CR>,
`gs` and `gb` in Visual mode with the preset, the line selector's keys). They
arrive as a mention, a snippet or both, as from the line selector, and the
prompt is shown again.

The first send after `gd` or |:Vergil-open| replaces the reference you
opened, so `@file` becomes `` `file#L12-L35` ``. Later sends go after the
prompt's cursor, after a reference rather than inside it, with spaces as
needed. |CTRL-^| goes back to the file for another selection. Files outside
the root are sent with their full path. If the file has unsaved changes,
the lines are sent as you see them, with a warning: the agent reads the file
on disk.

8. DIAGNOSTICS AND CODE ACTIONS                           *vergil-diagnostics*

  Check                                              Default severity
  Same file attached twice (paths normalized)        warn
  Attachment above `attachment_token_warning`        info
    (tokens estimated as bytes / 3)
  Mention range past the end of the file             warn
  `@file#range`: the range doesn't limit it          hint
  Mention target not found                           warn
  Attachment target not found                        info
  `@file` in fenced code that may still attach       hint
  `file#L3-L9` (`name`): the range no longer         warn
    matches that symbol (|vergil-symbols|)

Ordinary inline code that might be a path, prose and pasted logs aren't
flagged beyond the low-severity "attachment not found". Validation never
changes the buffer.

Code actions (`gra`): convert between attachment and mention (preferred as a
fix for duplicate, large and ranged attachments), update a drifted range to
its symbol, replace with snippet, add snippet below, and select lines.

==============================================================================
9. SUBMIT AND ABORT                                            *vergil-submit*

`:wq` doesn't exit Neovim while other windows are open, which leaves Claude
Code waiting, and quitting with modified buffers fails.

|:Vergil-submit| closes floats, writes the prompt, asks what to do with other
modified buffers (save all, discard or cancel; never silently), then exits.

|:Vergil-abort| asks the same question, writes the prompt file back as it
was when Neovim opened it, then exits with |:cquit|. Either restores the
prompt from before `Ctrl+G`, even if it was written in between.

10. COMMANDS                                                 *vergil-commands*

                                                                     *:Vergil*
:Vergil preview                                         *:Vergil-preview*
    Preview the reference or skill under the cursor.

:Vergil open [split|vsplit|tab]                            *:Vergil-open*
    Open the target of the reference or skill under the cursor.

:Vergil range                                             *:Vergil-range*
    Select lines for the reference under the cursor.

:Vergil snippet [both]                                  *:Vergil-snippet*
    Replace the ranged reference under the cursor with its lines; with
    `both`, keep it and add the lines below. Without a range, opens the line
    selector.

:[range]Vergil send [snippet|both]                         *:Vergil-send*
    Send [range] lines (default: the cursor line) of the current file to
    the prompt as a mention; `snippet` sends a verbatim snippet and `both`
    sends the two. See |vergil-send|.

:Vergil toggle                                           *:Vergil-toggle*
    Convert the reference under the cursor between attachment and mention.

:Vergil pick [attach|mention|skills|changed|commits]       *:Vergil-pick*
    Open |vergil-picker| on a tab: `all` (default), `attach` or `mention`
    (Files, in that mode), `skills`, `changed`, `commits`.
    `changed` lists files changed in git (modified, staged, renamed,
    untracked; not deleted) with their status, to attach. `commits` lists
    recent commits that touched the root, with a `git show` preview, and
    inserts `` `abc1234` (subject) ``; <C-d> inserts the commit's diff
    instead. See |vergil-git|.

:Vergil diff [staged|{rev}]                                *:Vergil-diff*
    Insert `git diff` below the cursor line as a fenced `diff` block,
    headed by the command. Without an argument, all uncommitted changes to
    tracked files (`git diff HEAD`); `staged` only staged ones; {rev} a
    revision or range such as `HEAD~1` or `main...`. Only changes under the
    root are shown, with paths relative to it. Warns when the diff is above
    `diagnostics.attachment_token_warning`. <Tab> completes `staged`,
    branches, tags and recent commits.

                                                                 *vergil-git*
vergil turns git state into prompt text and doesn't browse history; git is
optional. For history and diffs use vim-fugitive or diffview.nvim, for
finding commits telescope's `git_commits` and `git_branches`, and for hunks
gitsigns.nvim. blink-cmp-git completes commit hashes after `:` in prompt
buffers if you add it to their sources (`vim.b.vergil_enabled`); its `@` and
`#` GitHub/GitLab completions overlap vergil's triggers, so move them with
its `git_centers.github.mention.triggers` and `issue.triggers` options.

                                                         *vergil-git-objects*
`K` on a commit or branch in the prompt (`` `abc1234` ``, `` `main` ``,
`` `feature/x` (branch) ``) shows its message and changed files, or its recent
commits and ahead/behind. `gd` and |:Vergil-open| show the whole commit
(`git show`) or the branch's log in a read-only `vergil://git/...` buffer.
vergil asks git only on these keys, and doesn't flag the words as missing
files.

:Vergil submit                                           *:Vergil-submit*
    Write the prompt, settle other modified buffers, exit.

:Vergil abort                                             *:Vergil-abort*
    Settle other modified buffers, write the prompt back as it was, and
    exit with an error, which restores the previous prompt.

:Vergil enable                                           *:Vergil-enable*
:Vergil disable                                         *:Vergil-disable*
    Turn vergil on or off in the current buffer.

11. MAPPINGS                                                 *vergil-mappings*

vergil maps nothing by default. Normal-mode <Plug> mappings:

  <Plug>(vergil-snippet)        <Plug>(vergil-snippet-both)
  <Plug>(vergil-range)          <Plug>(vergil-toggle)
  <Plug>(vergil-preview)        <Plug>(vergil-close-preview)
  <Plug>(vergil-open)           <Plug>(vergil-open-split)
  <Plug>(vergil-open-vsplit)    <Plug>(vergil-open-tab)
  <Plug>(vergil-submit)         <Plug>(vergil-abort)
  <Plug>(vergil-pick)           <Plug>(vergil-pick-attach)
  <Plug>(vergil-pick-mention)   <Plug>(vergil-pick-skills)
  <Plug>(vergil-pick-changed)   <Plug>(vergil-pick-commits)
  <Plug>(vergil-pick-branches)  <Plug>(vergil-hover)
  <Plug>(vergil-pick-expand)    <Plug>(vergil-send)
  <Plug>(vergil-send-snippet)   <Plug>(vergil-send-both)

The pick mappings also exist in Insert mode. The send mappings also exist in
Visual mode, where they send the selected lines.

                                                        *vergil-keymap-preset*
`keymaps = { preset = true }` maps, in prompt buffers only:

  K         Preview (LSP hover); pressed again, closes it, or moves into it
            with `preview.on_repeat = "focus"` (Neovim's own behaviour)
  gs        Replace a ranged reference with its lines
  gb        Keep it and add its lines below
  gf        Open the reference; the native |gf| elsewhere
  <C-w>f    Open it in a split; the native |CTRL-W_f| elsewhere
  <C-w>gf   Open it in a tab; the native |CTRL-W_gf| elsewhere
  ZZ        |:Vergil-submit|
  ZQ        |:Vergil-abort|
  <Esc>     Close an open preview, also when focused; a normal <Esc>
            otherwise
  <C-g>     Open the picker on what you're typing (Insert mode) or on
            the word or reference under the cursor (Normal mode), and
            replace it with your choice

and, in Visual mode in other file buffers while a prompt is open, the line
selector's keys (`selector.keys`):

  <CR>      Send the selected lines to the prompt as a mention
  gs        Send them as a snippet
  gb        Send both

12. CONFIGURATION                                              *vergil-config*

                                                              *vergil.setup()*
Call `require("vergil").setup(opts)` once; it's optional. Defaults: >lua
  require("vergil").setup({
    agent = "claude",
    root = nil,
    activation = { filename_patterns = nil }, -- nil: { "claude-prompt-*.md" }
    mention = { format = "github", symbols = true },
    triggers = { attach = "@", mention = "@@", range = "#", skills = "/" },
    skills = { extra_items = {} },
    selector = {
      keys = { mention = "<CR>", snippet = "gs", both = "gb",
               symbols = "gO", cancel = { "q", "<Esc>" } },
    },
    completion = { native = false, reopen_on_backspace = true },
    files = { command = nil },
    keymaps = { preset = false },
    return_to_prompt = true,
    picker = {
      on_trigger = false, keys = {},
      tabs = { "all", "files", "changed", "branches", "commits", "skills" },
    },
    preview = { on_repeat = "close" },
    diagnostics = {
      attachment_token_warning = 20000,
      severity = {
        duplicate = "warn", large = "info", range = "warn",
        ignored_range = "hint", missing_mention = "warn",
        missing_attachment = "info", fenced = "hint", symbol = "warn",
      },
    },
  })
<
`root`                  Project root. Default: Neovim's startup directory.
`activation.filename_patterns`
                        File-name globs that turn vergil on.
`mention.format`        "github", "colon", or templates such as
                        `{ single = "{path}#L{start}",`
                        `  range = "{path}#L{start}-L{end}" }`. A template
                        starts with {path}, has a separator after it, and
                        puts {start} before {end}.
`mention.symbols`       Add the function or class name after a range that
                        covers exactly one. See |vergil-symbols|.
`triggers`              Completion and selector triggers. `range` must be a
                        single character.
`skills.extra_items`    Extra `/` items: `{ name, description?,
                        argument_hint? }`. Discovered items win name clashes.
`selector.keys`         Keys in the line selector.
`completion.native`     Enable built-in LSP completion in prompt buffers.
`completion.reopen_on_backspace`
                        Reopen the menu after Backspace inside a reference.
`files.command`         Discovery command run in the root, printing one
                        relative path per line. Default: rg, fd, git, then a
                        built-in scan; the first that runs wins, even when
                        it finds nothing (a root that .gitignore ignores
                        lists no files). To list ignored files too:
                        `{ "rg", "--files", "--hidden", "--no-ignore",`
                        `"--glob", "!.git" }`
`keymaps.preset`        See |vergil-keymap-preset|.
`return_to_prompt`      See |vergil-preview|.
`picker.on_trigger`     Open the picker on `@` and `/`. See |vergil-picker|.
`picker.keys`           Override picker keys. See |vergil-picker|.
`picker.tabs`           The picker's tabs, in order. See |vergil-picker|.
`preview.on_repeat`     `K` (preset) or |:Vergil-preview| with the preview
                        open: "close" it (default) or "focus" it.
`diagnostics.attachment_token_warning`
                        Estimated tokens (bytes / 3) above which an
                        attachment is flagged.
`diagnostics.severity`  "error", "warn", "info", "hint", or false to turn a
                        check off.

13. EVENTS AND API                                                *vergil-api*

                                                *VergilEnable* *VergilDisable*
|User| autocommands with `pattern = "VergilEnable"` / `"VergilDisable"`, fired
when vergil turns on or off in a buffer; `ev.data.bufnr` is the buffer.
`vim.b.vergil_enabled` is true in enabled buffers.

Lua API: `require("vergil")`
  `setup(opts)`           Configure.
  `enable(bufnr?)`        Turn on in a buffer.
  `disable(bufnr?)`       Turn off.
  `references(bufnr?)`    References in a buffer, with exact spans.
  `toggle()`, `preview()`, `open(how?)`
                          The actions behind the commands; they return
                          `ok, err`.

==============================================================================
14. LIMITATIONS                                           *vergil-limitations*

- Agent behaviour is undocumented and changes; see |vergil-observed|.
- Only the short-lived `Ctrl+G` Neovim is supported.
- vergil sees only the current prompt, not files attached earlier.
- `@words` in pasted text may be reported as missing files (Info).
- The large-attachment note is an estimate.
- Mentions with ranges are a convention Claude followed in testing; nothing
  enforces them.
- Plugin skill discovery and synced-skill naming are best effort.
- Skills with `user-invocable: false` are listed, as in Claude Code's menu.
- Format-on-save or whitespace trimming stops Claude Code from collapsing
  unchanged pasted text again.

==============================================================================
15. TROUBLESHOOTING                                   *vergil-troubleshooting*

Nothing happens when typing `@`
  Check `:echo b:vergil_enabled`, that Claude Code opens Neovim (it prefers
  `$VISUAL` over `$EDITOR`), and that a completion engine is active.

`Ctrl+G` does nothing
  If the editor fails to start, Claude Code silently keeps the prompt. Run
  the command in `$VISUAL` yourself to see the error.

Snippets or paths pop up while typing prose
  Limit the completion engine to the LSP source in prompt buffers; see
  |vergil-completion|.

Icons show as boxes
  Install a Nerd Font, or hide icons in prompt buffers. blink.cmp accepts a
  function for `completion.menu.draw.columns` that can drop "kind_icon" when
  `vim.b.vergil_enabled` is set.

`:wq` leaves Claude Code waiting
  Other windows or modified buffers keep Neovim open. Use |:Vergil-submit|.

Pasted text no longer collapses in Claude Code
  Something rewrote the prompt on save. See |:checkhealth| `vergil`.
